# 智能小车 · 浏览器端推理技术选型与分阶段路线规划

> 范围：教学平台（入门 KNN / 进阶 MLP / 高级 CNN / 拓展 YOLO-World）在 Web 端的模型推理框架选型。
> 结论先行：前三级用 **TensorFlow.js**（因为需要浏览器内训练），拓展关用 **ONNX Runtime Web + YOLO-World**（开放词汇 + WebGPU 实时性）。

---

## 1. TF.js 与 ort-web 的关系与定位

二者都是**浏览器端推理运行时**，但生态来源互补而非竞争：

| 维度 | TensorFlow.js | ONNX Runtime Web (ort-web) |
|---|---|---|
| 来源 | Google TensorFlow 官方 JS 移植 | 微软 ONNX 官方运行时 Web 版 |
| 吃谁的模型 | TF / Keras 生态（`.json`+权重、Keras） | 任意框架导出为 ONNX（PyTorch 为主） |
| 能否训练 | ✅ 浏览器内可训练 / 微调 | ❌ 纯推理，不训练 |
| 后端 | WebGL（主）/ WASM / WebGPU(实验) | WASM / WebGL / **WebGPU(成熟)** |
| 典型模型 | coco-ssd、mobilenet、自训 KNN/MLP/CNN | YOLOv8、YOLO-World、SegFormer、各类 PyTorch SOTA |

**核心关系**：当今检测 / 分割 / 多模态 SOTA 几乎出自 PyTorch → ONNX 线；TF.js 擅长“前端训练 + TF 生态模型”。一个 Web 应用可**同时**集成两者（TF.js 管前三级训练，ort-web 管 YOLO-World），互不冲突。

---

## 2. 架构差异要点

1. **模型格式**：TF.js 用 `model.json` + 分片权重（已离线下载到 `public/models/coco-ssd`）；ort-web 用**单一 `.onnx` 文件**（图+权重一体），更利于离线分发与量化。
2. **训练能力**：只有 TF.js 能 `model.fit()` 在浏览器训练——这是前三级教学核心。ort-web 无训练能力。
3. **后端成熟度**：ort-web 的 **WebGPU EP** 是当前浏览器端 GPU 推理最快、最稳定的路径；TF.js 的 WebGPU 后端仍偏实验，主力仍是 WebGL。
4. **算子覆盖**：ort-web 跑通用 ONNX 算子，新模型（YOLOv8 / YOLO-World）导出即跑；TF.js 需先转 TF 格式，对新架构适配滞后。

---

## 3. 分阶段选型与依据

### 阶段1 · 入门（KNN / MLP）
- **选型：TF.js（训练）**。
- **依据**：KNN 是最近邻（纯 JS 即可）；MLP 需要浏览器内训练——只有 TF.js 能 `fit()`，ort-web 不能训练。
- **模型兼容性**：自写小网络，无预训练权重。
- **性能**：样本量小，CPU/WASM 即够。

### 阶段2 · 进阶（MLP 调参 + 检测预热）
- **选型：TF.js 主导**；引入 **coco-ssd（TF.js）** 作封闭词汇检测演示，为拓展关铺垫。
- **依据**：仍需前端训练；coco-ssd 是 TF.js 原生模型，零成本接入（已离线化）。

### 阶段3 · 高级（CNN 卷积网络）
- **选型：TF.js（浏览器内训练 CNN）**；辅以 mobilenet（TF.js）推理演示。
- **依据**：教学核心是“从零搭卷积 / 池化 / 全连接并亲自训练”，必须用 TF.js。`useMobileNet.ts` 已是 TF.js。

### 阶段4 · 拓展（YOLO-World + 自动驾驶）
- **选型：ort-web + WebGPU（明确）**。依据：
  1. **模型来源**：YOLO-World 是 PyTorch 模型（基于 YOLOv8），官方 `export_onnx.py` 一键导出 ONNX；TF.js 无原生 YOLO-World，手工转会丢失开放词汇能力。
  2. **开放词汇（核心卖点）**：用**文本提示（text prompts）**检测任意类别——`person / car / red_light` 甚至中文，无需重训。这是超越 coco-ssd（固定 80 类）的亮点，必须走原版 ONNX + ort-web。
  3. **实时性**：ort-web WebGPU EP 远快于 TF.js WebGL，适合小车实时避障。
- **YOLO-World 接入优势**：
  - `export_onnx.py --custom-text prompts.json` 直接导出含自定义词汇的 ONNX；
  - 可动态传入文本提示实现零样本检测，不用重新导出模型；
  - ONNX 单文件 + INT8 量化：体积可↓~75%、速度↑~3×、精度保持 95%+；
  - 与 coco-ssd 形成**对照教学**：coco-ssd = 封闭词汇基线（TF.js），YOLO-World = 开放词汇进阶（ort-web）。
- **性能（近似，取决于设备 / WebGPU 支持）**：

| 后端 | coco-ssd (TF.js) | YOLO-World (ort-web) |
|---|---|---|
| WASM(CPU) | 3–8 FPS | 2–6 FPS |
| WebGL | 20–30 FPS | 15–25 FPS |
| **WebGPU** | 不适用(TF.js 实验) | **30–60+ FPS** |

## 4. 代码架构：InferenceEngine 双后端抽象

为解耦“检测框架”与“上层决策”，新增 `src/features/train/detectors/`：

- `types.ts`：`DetectorBackend` 接口、`DetectedObject`、`DetectOptions`、`DetectorEngine`。
- `cocoSsdBackend.ts`：`CocoSsdBackend`（TF.js + coco-ssd，本地离线优先，失败回退 CDN）。
- `yoloWorldBackend.ts`：`YoloWorldBackend`（ort-web + YOLO-World，WebGPU→WASM 回退，YOLOv8 风格解码 + NMS，letterbox 还原坐标，开放词汇文本提示）。
- `index.ts`：`createDetector(engine)` 工厂 + `AVAILABLE_DETECTORS` 元信息。

`YoloDetector.tsx` 页面按 `engine` 状态切换后端，并提供 YOLO-World 的**文本提示输入框**；决策逻辑 `decideDriving()` 与检测引擎完全无关，coco-ssd 与 YOLO-World 输出统一映射成 F/L/R/S 指令。

**离线 / 边缘部署**：coco-ssd 走 `npm run download:yolo-model`；YOLO-World 的 **ort-web wasm 运行时已由 Vite 插件自动托管**（`/models/yolo-world/wasm`，dev 中间件 + build 复制），无需服务器跑下载脚本。ONNX 模型在**页面内**加载：点「选择 ONNX 文件」上传已导出的 `.onnx`，或填模型 URL 后点「从 URL 加载」即可（浏览器内 `ort.InferenceSession.create`，纯客户端、不碰服务器）。`npm run download:yolo-world` 仅用于把 ONNX + 默认提示词**预置**到 `public/models/yolo-world/` 以便完全离线开箱即用。WebGPU 端侧推理 = 浏览器内边缘计算，零云端依赖。

## 5. 明确的分阶段技术路线规划

```
阶段1 入门  KNN/MLP          → TF.js（浏览器内训练，无预训练模型）
阶段2 进阶  MLP 调参 + 检测预热 → TF.js 主导；coco-ssd(TF.js) 作封闭词汇演示
阶段3 高级  CNN              → TF.js（浏览器内训练，mobilenet 推理演示）
阶段4 拓展  YOLO-World       → 切换 ort-web + WebGPU；coco-ssd(TF.js) 留作基线对比
```

**WebGPU 回退策略**：拓展关优先 WebGPU；不支持时自动回退 WebGL → WASM（`executionProviders: ['webgpu','wasm']`），保证兼容性。

**可选增强（非必需）**：若想展示“工业级 CNN 推理”，可补一个 ort-web 跑 ONNX-CNN 的对比 demo，但主线仍 TF.js，避免分散教学重点。
