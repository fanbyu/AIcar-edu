根据 MicroBlocks 串行协议（v2.09）的官方文档，以下是**完整的 OpCode（操作码）列表**及其详细功能说明。

为了便于理解，我将它们按照**通信方向**和**功能类别**进行了分类，并标注了它们是“短消息”还是“长消息”。

---

### 一、 IDE ➔ 开发板（电脑控制板子）`[0x01 - 0x0F]`
这些指令由电脑端（MicroBlocks IDE）发送，用于实时修改代码、控制程序运行或查询状态。

| OpCode | 名称 | 消息类型 | 功能说明 |
| :--- | :--- | :--- | :--- |
| **0x01** | Chunk Code | 长消息 | **发送代码块**：将编译后的二进制积木代码发送给板子（或板子响应“获取所有代码”时返回）。 |
| **0x02** | Delete Chunk | 短消息 | **删除代码块**：删除指定 ID 的代码块，并停止与之相关的任何运行中的任务。 |
| **0x03** | Start Chunk | 短消息 | **启动任务**：启动指定 ID 的代码块。如果已在运行，则中止并重启。 |
| **0x04** | Stop Chunk | 短消息 | **停止任务**：停止指定 ID 的代码块运行。 |
| **0x05** | Start All | 短消息 | **全部启动**：启动所有“当启动时”的脚本，并开始轮询“当 [条件]”的脚本（类似 Scratch 的绿旗）。 |
| **0x06** | Stop All | 短消息 | **全部停止**：停止所有任务和条件轮询（类似 Scratch 的红色停止按钮）。 |
| **0x07** | Get Variable Value | 短/长消息 | **获取变量值**：短消息按 ID 请求，长消息按变量名请求。板子会通过 `0x15` 响应。 |
| **0x08** | Set Variable Value | 长消息 | **设置变量值**：**实时编程的核心！** 包含 1 字节类型标志（1=整数, 2=字符串, 3=布尔值）和实际数据。 |
| **0x09** | Get Variable Names | 短消息 | **获取所有变量名**：板子会通过一系列 `0x1D` 消息返回所有变量名称。 |
| **0x0A** | Clear Variables | 短消息 | **清空变量**：清除所有变量名记录（通常在 IDE 中删除变量后调用）。 |
| **0x0B** | Get CRC | 短消息 | **获取校验和**：请求指定代码块的 CRC-32 校验和，用于验证代码完整性。 |
| **0x0C** | Get VM Version | 短消息 | **获取虚拟机版本**：请求板子的 VM 版本和硬件类型信息。 |
| **0x0D** | Get All Code | 短消息 | **获取所有代码**：请求板子发送所有存储的代码（包括二进制代码、源码字符串和变量名）。 |
| **0x0E** | Delete All Code | 短消息 | **删除所有代码**：停止所有任务，并从板子中删除所有代码及属性。 |
| **0x0F** | System Reset | 短消息 | **系统重置**：停止所有任务并重启硬件。 |

### 二、 开发板 ➔ IDE（板子主动汇报）`[0x10 - 0x19]`
这些指令由微控制器主动发送，用于通知电脑端程序的运行状态、输出结果或错误信息。

| OpCode | 名称 | 消息类型 | 功能说明 |
| :--- | :--- | :--- | :--- |
| **0x10** | Task Started | 短消息 | **任务已启动**：通知 IDE 指定 ID 的代码块已开始运行。 |
| **0x11** | Task Done | 短消息 | **任务已完成**：通知 IDE 指定代码块已执行完毕（无返回值）。 |
| **0x12** | Task Returned Value| 长消息 | **任务返回值**：代码块执行完毕并返回了一个值（编码方式同 `0x08`）。 |
| **0x13** | Task Error | 长消息 | **任务错误**：报告执行错误。包含 1 字节错误码和 4 字节的位置信息（代码块 ID + 指令指针 IP）。 |
| **0x14** | Output Value | 长消息 | **输出值**：当板子执行“打印”或“说”积木时，将结果字符串/数值发送给 IDE 显示。 |
| **0x15** | Variable Value | 长消息 | **变量值响应**：响应 IDE 的 `0x07` 请求，返回指定变量的当前值。 |
| **0x16** | VM Version | 长消息 | **版本信息响应**：返回虚拟机的版本字符串。 |
| **0x17** | Chunk CRC | 长消息 | **校验和响应**：返回指定代码块的 4 字节 CRC-32 值。 |
| **0x18** | Clear Graph | 短消息 | **清除图表**：通知 IDE 清除屏幕上的图表/绘图数据。 |
| **0x19** | Code Store Full | 短消息 | **存储空间已满**：警告 IDE，即使经过压缩，板子的代码存储空间也已耗尽。 |

### 三、 双向通信（IDE ⇄ 开发板）`[0x1A - 0x1D]`
这些指令可以在两个方向上流动，用于同步状态或触发事件。

| OpCode | 名称 | 消息类型 | 功能说明 |
| :--- | :--- | :--- | :--- |
| **0x1A** | Ping | 短消息 | **心跳检测**：IDE 发送，板子原样回复。用于确认连接是否仍然存活。 |
| **0x1B** | **Broadcast** | 长消息 | **广播消息**：**这就是您之前问到的“广播”机制！** 消息体是广播的字符串名称。IDE 发给板子可触发板子上的事件；板子发给 IDE 可触发电脑端的动画或逻辑。 |
| **0x1C** | Chunk Attribute | 长消息 | *(已废弃)* 曾用于同步代码块在屏幕上的 X/Y 坐标位置或源码字符串。 |
| **0x1D** | Variable Name | 长消息 | **变量名**：板子向 IDE 报告指定 ID 对应的变量名称（字符串）。 |

### 四、 其他与扩展消息 `[0x1E - 0x25]`

| OpCode | 名称 | 消息类型 | 功能说明 |
| :--- | :--- | :--- | :--- |
| **0x1E** | Extended Message | 长消息 | **扩展消息**：ID 字段指定子类型。例如子类型 `1` 用于设置“说”或“图表”积木的逐字节延迟时间（1-50）。 |
| **0x1F** | Enable BLE | 短消息 | **启用/禁用蓝牙**：第三字节为 0 则禁用 BLE 连接，非 0 则启用。不支持 BLE 的板子会忽略此指令。 |
| **0x20** | Chunk Code 16-bit | 长消息 | **16位代码块**：与 `0x01` 类似，但用于传输 16 位二进制代码（针对特定架构）。 |
| **0x21** | Code Space Used | 长消息 | **代码空间使用情况**：板子向 IDE 报告已使用的代码空间字节数。 |
| **0x22** | Snapshot Code | 长消息 | **代码快照到文件**：IDE 命令板子将当前代码保存为 `.ucode` 文件（仅限带文件系统的板子，如 ESP32）。 |
| **0x23-0x25**| Reserved | - | 保留供未来使用。 |

### 五、 高级功能：CRC 校验与文件传输 `[0x26 - 0xFF]`
针对带有文件系统（如 SD 卡或 Flash）的高级微控制器（如 ESP32、Raspberry Pi Pico）。

| OpCode | 名称 | 方向 | 功能说明 |
| :--- | :--- | :--- | :--- |
| **0x26** | Get All CRCs | IDE ➔ 板 | 请求板子发送所有代码块的 CRC 校验和。 |
| **0x27** | All CRCs | 板 ➔ IDE | 板子返回所有代码块的 CRC 列表（每条记录 5 字节：1 字节 ID + 4 字节 CRC）。 |
| **200** | Delete File | IDE ➔ 板 | 删除板子上的指定文件。 |
| **201** | List Files | IDE ➔ 板 | 请求列出板子上的所有文件。 |
| **202** | File Info | 板 ➔ IDE | 响应 `201`，返回文件大小（4 字节）和文件名。 |
| **203** | Start Reading | IDE ➔ 板 | 请求板子开始发送文件（包含 4 字节随机传输 ID 和文件名）。 |
| **204** | Start Writing | IDE ➔ 板 | 通知板子准备接收文件（包含 4 字节随机传输 ID 和文件名）。 |
| **205** | File Chunk | 双向 | **文件分块传输**：包含传输 ID、字节偏移量和实际数据字节。最后一个分块无数据，表示文件传输结束。 |

---

### 💡 核心总结：这些 OpCode 如何支撑 MicroBlocks 的体验？

1. **实时性**：当你拖动滑块时，IDE 瞬间发送 `0x08` (Set Variable Value)，板子立即更新内存，无需重新编译或烧录。
2. **事件驱动**：当板子上的角色碰到边缘时，板子发送 `0x1B` (Broadcast "hit_edge")，电脑端收到后立刻触发相应的动画，实现了软硬件的无缝联动。
3. **高可靠性**：所有长消息（如 `0x01`, `0x08`, `0x1B`）都严格遵循 `[0xFB, ..., 0xFE]` 的 framing 规则，配合 `0xFA`/`0xFB` 的 UTF-8 非法字节特性，确保了在嘈杂的串口环境中也能瞬间重新同步，不会把用户文本误认为指令。
