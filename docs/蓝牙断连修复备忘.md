# 蓝牙「推理就断 / 一点就断」修复备忘

> 状态：已修复并部署（2026-07-22）
> 关联：KNN 教学页（`src/pages/teaching/KnnTrainer.tsx`）+ 蓝牙层（`src/features/bluetooth/*`）

## 现象

- 无论**单张推理**还是**实时识别（自动驾驶）**，一点「推理」按钮，蓝牙连接状态就立刻变成「不可用 / 已断开」，UI 弹出重连按钮。
- 用户必须手动断开再连一次才能恢复，形成「推理就断 → 重连 → 再推理又断」的死循环。
- 小车其实没收到指令也不动（因为根本不是射频真断，是状态被污染）。

## 根因（简单架构 bug，非射频 / GPU / 性能）

`BluetoothPanel` 与 `KnnTrainer` **各自调用 `useBluetooth()`**，而旧版 `useBluetooth` 在组件挂载时 `new BleController()`、卸载时 `controller.disconnect()`：

1. 用户在 `BluetoothPanel` 点「扫描并连接」→ 连接建立在 **Panel 自己的实例 B** 上，全局 zustand store（`useBluetoothStore`）状态 = `connected`。
2. 点单张 / 实时推理 → `KnnTrainer` 的 `bt.send` 走它**自己的实例 A**，A 从未连过，`txChar` 为 `null`。
3. A 发送失败 → 旧代码调用 `onState('error', ...)` 把**全局 store** 的 state 从 `connected` 改成 `error`。
4. `BluetoothPanel` 读全局 store → 立即显示「已断开 / 重连」。

所以这是 **UI 误报循环**：物理连接从未真断，是另一个没连接的实例把全局状态覆盖了。

## 修复内容

### 1. `src/features/bluetooth/useBluetooth.ts`
- 将 `BleController` 改为**模块级单例**：新增 `getController()` 懒创建，所有 `useBluetooth()` 调用共享同一连接。
- 去掉组件卸载时的 `controller.disconnect()`，避免任一组件卸载误断全局连接。

### 2. `src/features/bluetooth/bleController.ts`
- `performWrite` 中 `txChar` 为空时：不再 `onState('error')`，改为 `console.warn('[BLE] 未连接，丢弃指令')`。
- 发送重试 3 次仍失败时：改为 `console.warn`，不再把全局 store 写成 `error`。
- 目的：杜绝「状态污染 → UI 误报断开」。

### 3. 保留的稳健兜底
- CPU 推理后端选项（`webgl` / `cpu`），之前为「蓝牙最稳」而加，作为兜底保留。
- 心跳保活（`setInterval` 1500ms ping）。

## 验证步骤

1. **硬刷新**（Ctrl+Shift+R）清掉旧缓存的单例 / store。
2. 在 `BluetoothPanel` **连一次**小车。
3. 点**单张推理** / 开**实时识别（自动驾驶）**：连接状态应保持不变，不再出现「断开 / 重连」提示，指令能正常下发。

若刷新连接后仍**真断**（面板真的变「已断开」且重连按钮自动出现），才说明是 ESP32 固件层 supervision timeout，需查固件。
